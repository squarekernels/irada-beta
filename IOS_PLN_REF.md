Preserve the initial-state branch.

## Architecture

- Build an independent SwiftUI app with app, unit-test, and UI-test targets. Use tabs in compact windows and a sidebar in wide windows. Keep a navigation path per destination and make Settings available globally. Details, history, and games return to the originating screen.
- Use URLSession, Codable, and Swift concurrency against the existing read-only API. Use /movies and /genres for Explore, /movies for Swipe, and /movies/{id} for details. Genie and Arcade share one lazy process-memory /catalog load. Coalesce concurrent loads, discard stale responses, and let failures retry. Keep catalog, questions, posters, and game state in memory.
- Use SwiftData for ratings, the saved movie snapshots required by history and scoring, and undo entries. Save rating changes and their undo entries atomically. Store appearance and game sound in UserDefaults. History and settings are available offline.
- Apply the approved Editorial colors, Fraunces and DM Sans, and Lucide outline vectors. Support Dynamic Type and Reduce Motion. Keep English, Spanish, German, and Portuguese strings and format arguments aligned. Film metadata, questions, and legal notices stay in their source language.
- Use dev.master.lumio as the development bundle ID and the approved Taste Ticket C raster as the interim icon. Use the Mac’s loopback API in Simulator and a configurable LAN endpoint for a device debug build. Limit local HTTP allowances to Debug and use the documented HTTPS testing service for Release. Confirm signing for a physical build. Production launcher artwork and App Store distribution require owner direction.

## Verification and parity updates

- Build with xcodebuild, run the relevant XCTest suite, and verify the stage on iPhone and iPad Simulator in light/dark, large text, and a non-English locale. Verify network success, controlled failure and Retry for networked features. Record actual results and limits in [iOS validation](../validation/ios.md). Track iOS 17 runtime coverage separately from the deployment target.
- Test paging races, interleaved undo and its retention limit, deterministic Genie scoring, Trivia timing and pause, and Puzzle cancellation using synthetic fixtures and a controllable clock where appropriate. Verify personal persistence across relaunch and app update. Test cold offline launch with history and settings available and catalog Retry visible.
- For each subsequent owner-approved Android behavior change, record its source commit or decision, iOS behavior, and acceptance case in the applicable stage. If iOS has shipped that stage, record the difference for owner review. Android validation is a source of scenarios for independent iOS checks.
